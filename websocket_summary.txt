================================================================================
REALCHAT ARCHITECTURAL SUMMARY - WEBSOCKET & RESILIENCE SYSTEMS
================================================================================

This document outlines the architecture, design patterns, and reliability layers
integrated into the RealChat application. It provides a file-by-file summary of 
where key concepts (Singleton, Resilience Queueing, and Socket Acknowledgement) 
are implemented.

--------------------------------------------------------------------------------
1. THE CORE CONCEPTS & WHERE TO FIND THEM
--------------------------------------------------------------------------------

[CONCEPT A] CLIENT CONNECTION SINGLETON PATTERN
- Purpose: Next.js renders pages on both server and client, and frequently re-mounts
  components during transitions. If a raw Socket.io-client connection is opened inside
  components, it creates duplicate handshakes, socket leakage, and performance lag.
- Implementation: Wrapped inside a lazy-loaded static class instantiator.
- File Path: chat-app/lib/socket.js (Lines 3 - 17)
- Code Reference:
  * Static property: `static instance = null;`
  * Static getter: `static getInstance() { ... }`
  * Export line: `export const socket = SocketService.getInstance();`
  * This singleton is shared globally by app/chat/page.jsx, Navbar.jsx, and ChatBox.jsx.

[CONCEPT B] OFFLINE RESILIENCE QUEUEING SYSTEM
- Purpose: When a user loses internet connectivity or the API server crashes, we must
  not lose their messages. Messages must be saved locally and sent automatically on reconnect.
- Implementation:
  * Persistent storage queue inside browser `localStorage` under key `realchat_offline_queue`.
  * Browser network state observers ('online' / 'offline' event listeners) attached to window.
  * Reconnection Engine: On network recovery, the singleton first attempts to save unsent direct/group messages permanently to the database (MongoDB or local JSON file fallback) via the Next.js API `/api/messages`, and upon database confirmation, broadcasts it real-time over Socket rooms, preventing data loss.
- File Path: chat-app/lib/socket.js (Lines 143 - 275)
- Code Reference:
  * `offlineQueue = [];` (holds unsent items)
  * `queueMessage(event, data, callback)` (serializes and pushes to localStorage)
  * `async flushOfflineQueue()` (performs async REST database persistence on reconnect, then emits socket signals)
  * `window.addEventListener("online", ...)` (automatically triggers reconnect and queue flushes)

[CONCEPT C] WEBSOCKET DELIVERY CONFIRMATION ACKNOWLEDGEMENT (ACK)
- Purpose: Ensures that a sender receives verified confirmation that their message was 
  successfully received and stored in the database.
- Implementation:
  * Three status indicators rendered next to message timestamps:
    - Spinning Clock (🕒): Sent locally, pending server confirmation.
    - Double Checkmark (✓✓): Delivered and saved in the database.
    - Warning Triangle (⚠️): Failed to send after timeout/outage.
  * Client-side emit timeouts to handle slow connections.
- File Path:
  * Client: chat-app/lib/socket.js (Lines 143 - 170) -> emitMessage sends data with an acknowledgment callback and a 6-second timeout.
  * Server: chat-app/server.js -> `socket.emit("send-message", payload, callback)` fires a callback response upon DB insertion.
  * UI renderer: chat-app/components/Message.jsx -> Renders clock, double-check, or warning based on `message.status`.

--------------------------------------------------------------------------------
2. COMPONENT FILE REGISTRY & PURPOSE
--------------------------------------------------------------------------------

* chat-app/lib/socket.js [NEW]
  - Core WebSocket client singleton. Controls status subscriptions, network listeners,
    and handles the local resilience queue and acknowledgment callbacks.

* chat-app/server.js [MODIFIED]
  - Upgraded real-time server coordinating isolated private rooms (`room:{userA}-{userB}`),
    isolated group rooms (`group:{groupId}`), delivery confirmation triggers, typing status,
    and background push notifications for offline users.

* chat-app/app/chat/page.jsx [MODIFIED]
  - Main chat dashboard. Resolves authentications, fetches direct contacts and groups,
    mounts the viewport-level group modal, updates dynamic typing states, and subscribes 
    to offline re-sent success handlers.

* chat-app/components/Sidebar.jsx [MODIFIED]
  - Renders the chat list tab segments ("Chats" and "Groups"), filters participants,
    and triggers the viewport-level group creator.

* chat-app/components/ChatBox.jsx [MODIFIED]
  - Chat thread frame. Renders dynamic group rosters, lookups participant names,
    and manages attachments and input fields.

* chat-app/components/Message.jsx [MODIFIED]
  - Chat message bubbles. Resolves user names and generates unique, consistent color 
    signatures for group participants, and displays animated real-time status indicators (🕒 / ✓✓ / ⚠️).

* chat-app/components/NotificationBell.jsx [NEW]
  - Pulsing dropdown alerts with unread counts and select triggers, playing premium audio.
